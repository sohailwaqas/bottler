# NOTE: netifaces and psutil are intentionally NOT listed here.
# They are optional "[hardware]" extras of licensingpy used only to sharpen
# hardware-fingerprint uniqueness; licensingpy already falls back to
# uuid.getnode() / os.cpu_count() when they're absent (see auth/activation.py
# for why hardware-fingerprint checking is disabled in this build anyway).
# netifaces in particular has no pre-built wheel on many Windows/Python
# combinations, which forces pip to compile it from source and fail with
# "Microsoft Visual C++ 14.0 or greater is required" — so we simply don't
# install it. If you want sharper hardware binding and have the C++ Build
# Tools installed, you can add `licensingpy[hardware]` yourself.
# Streamlit is PINNED to an exact version deliberately. This app uses the
# newer width='stretch'/'content' string API (st.dataframe, st.plotly_chart,
# st.form_submit_button, etc.), which behaves very differently across
# versions:
#   - Streamlit < ~1.49: `width` doesn't exist as one of these calls' params
#     at all (only `use_container_width=True/False`).
#   - Streamlit ~1.49-1.6x transitional builds: `width` exists but expects
#     an INTEGER pixel value — passing the string 'stretch' raises
#     `TypeError: 'str' object cannot be interpreted as an integer`.
#   - Streamlit (current, this build was tested on 1.63.0): `width` accepts
#     'stretch' / 'content' / an int.
# A loose ">=" constraint here previously let pip (or a stale/offline
# mirror) resolve to a version in that incompatible middle band, which
# surfaced as inline errors specifically on the pages with the most
# tables/charts (Stock Overview, Sales History, Target Overview). Pinning
# exactly removes that whole class of bug.
